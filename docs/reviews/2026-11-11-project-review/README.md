## 复核后必须修正的认识

- **会话串读/误删真实存在**，真实 SessionStore 已复现；HTTP 会先解析有损 ID，其删除对象取决于目录枚举结果，不能说每次都双删。B1-01 与 B5-02 必须分别验收。
- **后台记忆范围问题有前提**：目录内既有链接指向普通可读外部目标；不能扩写成所有平台可读取任意凭据。技能循环缺少的是普通循环已有的有限次补验/交付提示，普通循环也不是硬完成门。
- **任务隔离遗漏同时涉及账号和 Agent**。配置掩码不只是显示错误：删除/重排 Agent 数组可让额度恢复到另一 Agent 的旧值；配置合并还会让 Provider 协议无法切回被省略的默认值。
- **WeCom 正文丢失也发生在媒体成功时**。常规自动会话 ID `default:123` 的前端往返可以成功，确定出错的是有歧义的自定义/历史 ID 及事件匹配。
- **Rust 验证已恢复可用**：默认工具链为 1.92，但本机已安装 1.96。本轮明确指定 RUSTC/RUSTDOC 后，实际通过 core 132 + storage 105 = **237 项测试**，并完成真实 crate API 探针。旧报告“Rust 无法运行”不再是当前总体结论。

## 设计约束与迁移要求

1. **会话迁移不能猜归属。** 旧 stem 有歧义时明确报错或进入可核验迁移流程；不得删除另一会话“解决冲突”，不得只排序使错误选择稳定。新增无损 handle 后保留明确的旧格式兼容规则，历史、event、memory、tool-results 和 cache 使用同一身份。
2. **授权使用完整资源和来源。** 工具策略、脚本工具声明、执行环境标签均不能替代 PathPolicy；任务列表过滤不替代详情/取消/检查点恢复授权。缺身份旧记录须有显式兼容策略，不回落到 channel/chat 弱匹配。
3. **配置保留未知字段不等于复活已删除值。** 明确 schema 字段、动态 map、默认值及删除语义；秘密按精确路径/类型识别，数组恢复按稳定 ID；逐模型限额必须贯穿 Provider 请求或移除无效输入。
4. **并发调度先定义任务生命周期。** 启动、完成、超时、取消、steering、重试、删除/禁用要有一致状态；不要只并发化 run_tick 或扩大 TTL。尚未证实的重复副作用需用受控任务验证后决定是否另立项。
5. **失败必须保全既有产物。** 下载和安装要先验证再提交；部分媒体成功要有明确返回契约；有限次技能补验结束后如仍未满足契约，应如实保留状态，不能假定已通过。
