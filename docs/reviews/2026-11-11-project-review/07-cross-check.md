## 证据复核与去重

| 主题 | 复核结论 |
| --- | --- |
| 会话删除与路径隔离 | B1-01 的 canonical/legacy 冲突在纯函数验证中成立，`SessionStore::clear` 确实无条件删除第二路径，HTTP session delete 是真实入口。B5-01 是另一独立根因：斜杠 context 未按 agent 分目录；WS 和普通渠道都有同类错误，合为一项。 |
| 后台/技能授权 | B2-01 的后台 shell 只检查字面 operand，普通全盘只读沙箱允许跟随 memory 中的外部 symlink；B3-01 的 Rhai 则经另一嵌套 dispatcher，缺失 PathPolicy，默认文件工具 PermissionSet 也不能兜底。两条是不同执行入口和修复位置，各计一次。 |
| ZIP 写边界 | B3-02 检查了外层 file_ops 只提取 destination、解包仅拒绝归档内链接、File::create 跟随目标侧既有链接的完整链。已存在的目标链接足以触发，不依赖概率性 TOCTOU；Gateway 文件 API 的 TOCTOU 未证明，未混计。 |
| 账号任务隔离 | B4 确认 Telegram 两 bot 可具有相同 chat_id、不同 account_id；B2 核实 TaskInfo/工具 wrapper/自动摘要只按 channel/chat 匹配，统一归 B2-04。自动摘要补充了“有匹配的 running typed task 且预算未耗尽”的前提，不声称仅有 completed task 就会自动触发。 |
| 预算与 usage | B2-03 丢弃权威预算状态的阈值确为 64，不是数千或无限并发。B4-01 的 Anthropic `message_start.message.usage` 无结构体字段，message_delta 又整体覆盖；缺失输入最后按 0 记账。两者根因独立。 |
| 配置契约 | B1-02 恢复被删除的动态 map key；B1-03 写盘前验证比启动弱；B1-04 把数字改成字符串，但原样回写的 mask 可恢复，不能扩大为必然写坏配置。三项分别保留。 |
| 前端身份与事件 | 真实 store 最小复现确认 B5-02 和 B5-03。再次读 `chat-page.tsx` 后，收窄 B5-02：正常自动 id 经冒号/下划线往返可恢复，实际缺口是字面下划线被错发/错取消，以及不同原始 id 在事件比较中碰撞。HTTP 列表的 session_id_from_file_stem 也存在同类碰撞，作为同一跨层身份问题记录，不假设服务端所有 ID 接口已无损。reset/error 缺过滤是独立问题，完全不同的 id 也能触发。 |
| 发布与安装 | B6-01 四平台文件名分类均实际 no_match；B6-02 正常后缀误作 grep 选项，release 查找失败。这两项当前入口可达。校验失败仍安装的安全问题依赖先绕开/修复查找故障，单独说明，不加入当前确认 24 项。 |
| 评测可信度 | B6-03 实际调用项目 runner 得到 bytes 输出并使 json.dumps 报错。3 个 infra 脚本通过只能证明其现有断言；B6 已说明为何 manifest 分类和安装成功路径未被这些断言覆盖。 |
