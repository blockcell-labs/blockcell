# 概览与核心概念

[文档首页](README.md) · 下一篇：[快速开始](02-quickstart.md)

## 要解决的问题

LLM 可以生成补丁，但“生成了能编译的补丁”不足以证明 Agent 变好了。补丁可能损伤既有能力、依赖被改写的测试、增加工具调用成本，或者只在一次偶然运行中成功。

Genesis 把自改进拆成可审查的实验：固定初始源码与评测器，让当前 Parent 提出假设、实现小补丁，然后在相同任务上比较 Parent 与候选。控制器保存补丁、逐题结果、模型用量和判定原因。没有候选晋级也可以是有效实验结果。

进化单位是 **Blockcell 源码版本及其重新构建的二进制**。每轮使用被选中的父代二进制完成诊断、补丁和评审，候选成为父代后也能承担这些任务。补丁受路径规则约束，Supervisor、冻结评测源码等受保护。模型权重和运行中的宿主 Rust 进程位于这个实验闭环之外。

## 一次实验的直观例子

假设当前 Agent 在若干工具参数题上失败：

1. 控制器评测 Parent，将允许用于诊断的失败证据交给它。
2. Parent 输出两个结构化假设，例如修复参数解析和修复工具结果处理。
3. 两个候选各自从 Parent SHA 创建 detached worktree，分别实现补丁。
4. 控制器格式化改动、编译、比较静态检查和依赖审计，再执行能力评测。
5. 候选如果修复 3 题、破坏 1 题，净修复数是 2；它还必须通过安全、holdout、性能和标准修改自检，才可能晋级。
6. 证据不足或收益不足时记录原因，不用模型自述代替验收结果。

这是流程示例，不是某次真实改进的成绩声明。题目身份、评测重复次数和其他门槛会影响实际判定，详见[评测与晋级](04-evaluation.md)。

## 核心对象

| 名称 | 含义 |
|---|---|
| Supervisor | 可信 Python 控制器，掌管进程、状态、预算、评测与判定 |
| Genesis-0 | 初始锁定源码构建出的 Agent，也是回退基点 |
| frozen | 固定在 Genesis-0 SHA 的 worktree，提供可信评测源码 |
| Parent | 本轮被选中、负责 diagnose / patch / review 的 Agent 版本 |
| Candidate | 从 Parent 源码派生、尚未证明满足晋级条件的候选 |
| Hypothesis | 结构化改进假设，关联失败、根因、文件和验证方案 |
| Archive | SQLite 实验记录组件；也用作“保留但未晋级”的判定名，需按上下文区分 |
| Promotion | 将合格候选保存为本地谱系版本，并允许后续选择它 |
| holdout | 只用于判定、不向诊断阶段提供题目与轨迹的保留评测集 |

`PROMOTE` 是判定；数据库中相应 Agent 的状态是 `PARENT`。`ARCHIVE` 并不自动意味着能当 Parent：还要通过资格检查，高风险和自检失败版本不能进入抽样池。

## Genesis 与 Blockcell 的关系

Blockcell 是执行模型推理与工具操作的 Rust Agent。Genesis 通过其命令行接口调用指定版本的二进制，不要求把 Supervisor 嵌入 Rust 运行时。每轮诊断、修改和评审由该轮 Parent 自己的二进制执行，之后再运行候选二进制接受评测。

Genesis 控制模型入口：候选通过本地计量代理访问 OpenAI 兼容服务，真实 key 留在 Supervisor 侧。切换服务通常只需改接口地址、模型与单价，不需要写站点专用 Provider。

## 当前能力与边界

当前实现涵盖源码锁定、独立 clone/worktree、两个候选、原生沙箱、逐题评测、相对门禁、用量计量、预算阻断、持久化恢复、谱系保存与本地报告。具体实现入口见[架构](03-architecture.md)。

当前仍有明确限制：

- 原生沙箱共享宿主内核，不能提供虚拟机级隔离；初始可信源码在宿主构建。
- “没有新增 advisory”只说明相对 Parent 的审计结果，不能证明 Parent 无漏洞。
- 费用来自 usage 与配置单价，存在未知用量和在途请求超支的可能，不是账户账单。
- `pr_draft.md` 是本地草稿文件，程序不会自动创建远端 PR、push 或发布产品。
- 标准修改自检只验证一项固定修改任务，不能证明开放任务上的普遍自改进能力。
- 评测配置和题库需要可信维护；跨平台支持、长期稳定收益和抗攻击能力都需要独立证据。

面向生产的后续工作包括更强隔离、依赖治理、跨平台验收、更广泛的对抗测试和长期实验复现。它们是改进方向，不能用当前测试通过数代替。

评估递归改进收益时，应记录每轮父代和候选 SHA，检查晋级版本是否实际参与后续轮次，并在未用于晋级选择的独立任务上复测收益。现有回归测试覆盖控制流程和门禁，真实模型的多代收益仍待实验验证。
